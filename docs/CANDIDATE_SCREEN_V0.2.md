# 候选点位初筛 v0.2

## 定位

v0.2 不再只输出“资料是否完整”，而是把现有门店经营样本接入候选点位判断，优先回答：

- 这个候选点位现在能不能进入经营复核。
- 如果不能，当前最该补什么资料。
- 它可以参考哪些现有正向/风险样本。
- 外部选址情报应不应该现在查，以及先查什么。

## 数据输入

- 候选点位资料治理结果：`data/staging/candidate_screen.csv`
- 现有门店经营样本：`data/staging/site_benchmark.csv`
- 经营样本分位阈值：`data/staging/site_benchmark_stats.csv`

## 输出

- 输出文件：`data/staging/candidate_screen_v2.csv`
- 生成脚本：`scripts/build_candidate_screen_v2.py`

核心字段：

- `判断层级`：A 可进入经营复核；B 可做租售比预判；C 可做资料补齐判断；D 仅可排资料优先级。
- `推荐等级`：优先复核、签约前后补经营模型、优先补租金、优先补营收假设、优先补调研、已开业回填复盘、待建城市样本、资料池待筛等。
- `正向对标样本`：优先同城正向样本；同城没有时明确标记为跨城参考。
- `风险对标样本`：优先同城风险样本；同城没有时明确标记为跨城参考。
- `外部情报优先级`：P1 表示应辅助当前推进或验证判断；P2 表示内部资料补齐后再查。

## 当前结果

基于现有数据，v0.2 共覆盖 236 个候选项目：

- 优先复核：1 个。
- 签约前后补经营模型：4 个。
- 优先补租金：21 个。
- 优先补营收假设：2 个。
- 优先补调研：14 个。
- 已开业回填复盘：85 个。
- 待建城市样本：34 个。
- 资料池待筛：75 个。

判断层级分布：

- A-可进入经营复核：1 个。
- C-可做资料补齐判断：35 个。
- D-仅可排资料优先级：200 个。

## 当前洞察

- 经营数据和租金基准已经可以支持现有门店样本分层，问题不在经营数据接入。
- 候选点位侧仍缺大量租金、营收、调研报告链接、商圈等级和商场评级字段，导致多数项目不能直接形成租售比判断。
- 已开业候选项目数量较多，应优先回填真实经营表现和真实租金，转化为正反样本库，而不是继续停留在候选表状态。
- 深圳、杭州等非上海城市的现有同城样本较少，同城正向样本不足；这些城市的候选项目需要外部情报和跨城类比一起判断。
- 外部情报第一批不应全量抓取，应优先服务 P1 项目：洽谈中、调研中、报批中、已签约且内部资料部分具备的候选点位。

## 下一步

1. 回填 21 个“优先补租金”项目的月租金、物业费、面积和日租金。
2. 对 4 个“签约前后补经营模型”项目补齐租金、预期月营收和业绩驱动假设。
3. 对 14 个“优先补调研”项目补选址调研报告并回填候选表链接。
4. 把 85 个“已开业回填复盘”项目与真实经营表现合并，形成正反样本库 v0.1。
5. 再启动 P1 外部选址情报包，不先做全量爬取。
