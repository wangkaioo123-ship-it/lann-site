# AI任务清单 v0.1

本文档定义连锁经营部 AI 矩阵第一阶段的标准任务。标准任务用于替代“某个模型做某件事”的说法，后续模型可插拔、prompt 版本管理和评测样本都围绕任务展开。

## 任务总览

| 任务ID | 中文名称 | 归属项目 | 当前状态 |
|---|---|---|---|
| `feishu_bot_inbox_ingest` | 飞书机器人收件箱摄取 | 跨项目/工作OS | 待实现 |
| `work_item_orchestration` | 事项编排 | 跨项目/工作OS | 最高优先级，先轻量化 |
| `meeting_recap_extract` | 会议复盘提取 | 工作OS | 待设计 |
| `decision_source_distill` | 判断源候选提取 | 工作OS | 已有规则，待标准化 |

| `site_survey_fact_extract` | 选址调研报告事实抽取 | lann-site | 已有脚本，待 schema 化 |
| `ops_root_cause_analysis` | 经营表现归因 | lann-site | 已有数据基础，待任务化 |

| `executive_decision_brief` | 王凯参谋简报 | 跨项目 | 待设计 |

## 1. feishu_bot_inbox_ingest

目的：从飞书机器人会话读取王凯显式发来的文字、截图、语音、链接和转发消息，生成原始资料包 `source_packet`。

输入：

- 飞书机器人消息。
- 飞书妙记链接。
- 飞书云文档链接。
- 微信截图。
- 语音说明。
- 飞书转发消息。
- 电话/想法补录。

输出：

- 资料类型。
- 来源通道。
- 时间。
- 原始链接/附件引用。
- 文本或语音转写。
- 简要摘要。
- 关联对象。
- 关联项目。
- 是否需要展开读取。

权限级别：L1 只读 + L2 生成；不自动全量监听所有飞书聊天。

当前状态：待实现。作为 `work_item_orchestration` 的前置入口。

## 2. work_item_orchestration

目的：把飞书待办、会议结论、项目日志、工作OS候选和日常沟通事项编排成“今日应该如何处理”的关系视图。

输入：

- 飞书待办。
- 飞书消息/文档中的事项。
- 飞书妙记和会议复盘。
- `lann-site` 当前项目日志与分析缺口。
- `lann-dashboard` 项目状态。
- 工作OS 判断源候选。
- 王凯临时补充的微信/电话事项。

输出：

- 今日必须执行事项。
- 可以合并处理事项。
- 需要先补资料再判断的事项。
- 可能影响原方案的事项。
- 建议王凯亲自看的事项。
- 可交给别人推进的事项。
- 事项之间的依赖、冲突、重复和组合机会。

权限级别：L1 只读 + L2 生成；不自动改飞书待办、不自动派任务、不自动发消息。

当前优先级：最高。第一阶段先做轻量模板和 schema，不接自动化。

评测样本来源：王凯每日待办、飞书会议结论、候选点位资料缺口、dashboard 项目状态、工作OS判断源候选。

## 3. meeting_recap_extract

目的：把会议纪要、飞书妙记、会后补充内容转成可执行复盘。

输入：

- 飞书妙记文本。
- 会议文档。
- 会后补充说明。

输出：

- 会议主题。
- 参会对象。
- 关键事实。
- 已定决策。
- 未决问题。
- 风险。
- 待办。
- 关联业务对象。
- 是否进入工作OS候选。

权限级别：L1 只读 + L2 生成。

评测样本来源：历史会议纪要、飞书妙记、CEO 对齐会议、选址复盘会议。

## 4. decision_source_distill

目的：把重要讨论、方案、复盘、业务口径沉淀为判断源候选。

输入：

- 本次对话。
- 会议复盘输出。
- 方案文档。
- 关键决策记录。

输出：

- 判断内容。
- 适用模块。
- 来源。
- 置信度。
- 状态。

权限级别：L2 生成；写入工作OS候选按既有规则执行；进入正式源需王凯确认。

评测样本来源：已写入工作OS的判断源候选、DECISIONS.md。

## 5. site_candidate_screen

目的：判断候选点位资料是否足够进入复核，并给出初筛结论和资料缺口。

输入：

- 扩展管理候选项目表。
- 选址调研报告结构化事实。
- 现有门店经营基准分位。
- 租金、面积、预期营收等商务字段。

输出：

- 初筛结论。
- 核心证据。
- 缺口字段。
- 租售比估算。
- 租售比风险。
- 相似样本。
- 下一步动作。

权限级别：L1 只读 + L2 生成；写回候选表为 L3，需确认。

当前基础：

- `scripts/build_candidate_screen.py`
- `data/staging/candidate_screen.csv`

待补：

- 输出 schema。
- 评测样本。
- 判断口径版本号。

## 6. site_survey_fact_extract

目的：把选址调研报告中的场地、商务、竞品、市调、工程、投资等信息结构化。

输入：

- 飞书调研报告链接。
- 电子表格或 wiki 文档内容。

输出：

- 场地信息。
- 租金/物业/月成本。
- 面积。
- 商圈/商场评级。
- 竞品摘要。
- 点评摘要。
- 工程条件。
- 风险机会。
- 稳定营业额预期。
- 总投入。
- 来源链接。

权限级别：L1 只读 + L2 生成。

当前基础：

- `scripts/extract_site_survey_facts.py`
- `data/staging/site_survey_facts.csv`

待补：

- 抽取字段 schema。
- 异常字段校验。
- 口径说明。

## 7. ops_root_cause_analysis

目的：解释门店经营表现好/差的原因，并判断其是否适合作为选址样本。

输入：

- BI 月度经营数据。
- 飞书租金数据。
- 门店基础信息。
- 新客、客单、理疗师产值。
- 门店状态。

输出：

- 经营表现分层。
- 租金压力。
- 新客问题。
- 客单问题。
- 产能问题。
- 样本角色。
- 选址使用建议。

权限级别：L1 只读 + L2 生成。

当前基础：

- `scripts/build_site_benchmark.py`
- `scripts/build_site_performance.py`
- `data/staging/site_benchmark.csv`

待补：

- 归因规则版本。
- 正反样本标注评测。

## 8. external_site_intel

目的：围绕候选点位收集外部信号，补充商圈、竞品、客流、话题、新闻和区域风险。

输入：

- 候选项目名称。
- 地址/商场地点。
- 城市。
- 可选：经纬度。

输出：

- POI 摘要。
- 竞品数量。
- 交通/办公/住宅/商业密度。
- 新闻摘要。
- 口碑/内容样本摘要。
- 外部机会。
- 外部风险。
- 数据来源。
- 抓取时间。
- 可信度。

权限级别：L1 只读 + L2 生成；不做绕登录、绕反爬或未授权批量抓取。

第一阶段范围：

- 先设计 schema。
- 先做地图/POI + 新闻。
- 点评/小红书先采用人工链接样本 + AI 摘要。

## 9. dashboard_insight_summary

目的：把 dashboard 页面或筛选结果解释成人能快速行动的摘要。

输入：

- dashboard 当前筛选条件。
- 结构化结果数据。
- site 分析输出。

输出：

- 页面摘要。
- 异常解释。
- 优先处理对象。
- 风险标签。
- 下一步建议。

权限级别：L1 只读 + L2 生成。

待补：

- dashboard 数据契约。
- AI 字段展示规范。

## 10. executive_decision_brief

目的：把复杂业务问题压缩成王凯可直接决策的选项。

输入：

- site 分析结果。
- dashboard 状态。
- 工作OS判断源。
- 会议复盘。
- 当前问题上下文。

输出：

- 问题定义。
- 选项 A/B/C。
- 推荐方案。
- 风险和代价。
- 沟通话术。
- 下一步行动。

权限级别：L1 只读 + L2 生成；不直接执行写入或发消息。

待补：

- 决策简报格式。
- 王凯认可样本。
