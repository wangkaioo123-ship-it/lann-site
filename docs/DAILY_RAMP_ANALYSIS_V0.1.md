# 新店日级爬坡分析协议 v0.1

## 目的

当新店尚无完整自然月，或开业首月只有零碎经营日时，使用 Hanson 日结数据判断开业爬坡、数据完整性和短期风险，不把不完整月强行包装成月度好店结论。

## 基本原则

1. 日级分析是月度 Gate 的前置观察层，不替代月度经营结论。
2. 缺失日结不能按 0 营收处理；只有确认营业且完成结算的日期才进入日均计算。
3. 开业零碎月保留在日级趋势中，但不进入完整月的月均营收、CV 和近 3 月变化。
4. 新客、营收可按日观察；留存率和返店频次具有周期性，优先使用滚动 28 日或完整月。
5. 比较时优先使用同店同星期、同生命周期和同 SABC 类型，避免周末 / 工作日结构不同造成误判。

## 数据量分层

| 已完成结算日 | 可输出内容 | 不允许输出 |
|---:|---|---|
| 1–6 日 | 数据完整性、累计营收、累计新客 | 趋势判断、月度推算、好坏结论 |
| 7–13 日 | 7日均值、工作日 / 周末差异、异常日提示 | 正反样本定性 |
| 14–27 日 | 14日趋势、同星期环比、初步爬坡判断 | 完整月 Gate |
| 28 日以上 | 滚动28日营收、新客、预计月营收和预计租售比 | 完整好店结论 |
| 3个完整月 | 临时经济性与趋势判断 | 成熟店结论 |
| 6个完整月 | 正向 / 反向观察样本 | 完整好店结论 |
| 12个完整月 | 完整经济性、稳定性和客户健康 Gate | — |

## 完整日与完整月

### 完整日

- 门店当天计划营业；
- 店长日结已完成；
- `prod_amt` 字段存在；
- 数据不是重复记录；
- 若确认为闭店、停业或系统故障，单独标记，不自动补 0。

### 完整月

建议同时满足：

- 不是开业零碎月；
- 已跨过月末结算；
- 应营业日的日结覆盖率不低于 80%；
- 缺失日期已列入质量问题表。

80% 是首版技术阈值，用于防止少量漏结算让整月不可用；正式业务判断仍应优先使用接近全量结算的月份。

## 日级指标

1. 日均营收：完整结算日营收合计 / 完整结算日数。
2. 滚动7日、14日、28日营收与新客。
3. 工作日日均与周末日均，避免星期结构误导。
4. 预计月营收：日均营收 × 当月预计营业日；必须同时展示已结算覆盖率。
5. 预计租售比：月租金 / 预计月营收；只标“暂估”。
6. 日均新客和新客 / 营收关系，用于识别“有客流但承接弱”。
7. 与同 SABC 类型、同生命周期门店的日均分位。

## 输出状态

- `数据不足`：少于 7 个完整日。
- `爬坡观察`：7–27 个完整日。
- `月度暂估`：至少 28 个完整日，但尚无完整月。
- `月度观察`：至少 3 个完整月。
- `样本观察`：至少 6 个完整月。
- `完整评估`：至少 12 个完整月。

所有日级输出必须显示：数据截止日、完整日数、应营业日数、覆盖率和是否包含开业零碎月。

## 与 SABC 的关系

- SABC 用于选择可比门店和规模预期，不用于掩盖经济性结果。
- S 类新店与其他 S 类旗舰店比较日均营收、新客和爬坡速度。
- A/B/C 类分别建立同类日均基准；在样本不足时逐级放宽到相邻分类，但必须标明降级比较。
- 租售比仍使用统一事实值；战略例外单独说明。
