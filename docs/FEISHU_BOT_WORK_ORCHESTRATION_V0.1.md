# 飞书机器人事项编排项目 v0.1

本文档定义“飞书机器人 + 事项编排”的最小可行方案。目标是把王凯日常资料入口、每日提醒和事项编排输出都放到飞书机器人里，减少复制、整理、找文档、切换 CMD 的成本。

## 一、项目定位

项目名称：飞书机器人事项编排

承载项目：`C:\Users\王凯\lann-work-bot`

定位：

- 飞书机器人是日常 AI 入口。
- `inbox_ingest` 负责摄取机器人收到的原始资料。
- `work_item_orchestration` 负责事项编排。
- `project_status_read` 负责读取 `lann-site`、`lann-dashboard`、工作OS 的项目状态。
- 输出回到飞书机器人会话。

一句话：

王凯像平时发消息一样，把会议、微信截图、语音想法、飞书链接丢给机器人；机器人每天晚上提醒同步资料，并输出今日事项编排。

## 二、默认决策

### 1. 入口

入口使用飞书机器人，不使用飞书文档收件箱，不使用本地 inbox 文件夹，不要求王凯在 CMD 粘贴内容。

### 2. 提醒时间

默认每日 21:30 提醒：

```text
今天有需要同步给 AI 的会议、微信截图、电话结论、临时想法或项目事项吗？
直接发给我即可。发送“开始编排”后，我会读取今天资料并输出事项编排。
```

提醒时间后续可改。

### 3. 输出位置

默认输出回同一个飞书机器人会话。

输出内容包括：

- 今日事项编排。
- 关系提醒。
- 可能影响原方案的事项。
- 建议王凯亲自看的事项。
- 可交给别人推进的事项。
- 需要沉淀到工作OS的判断源候选。

### 4. 权限边界

机器人允许：

- 接收文字、截图、语音、链接、转发消息。
- 读取被显式发给机器人的飞书云文档/妙记链接。
- 读取本地项目状态文件。
- 生成事项编排。
- 生成会议复盘。
- 生成判断源候选草稿。

机器人不允许自动做：

- 自动全量监听所有飞书聊天。
- 自动读取未显式转发/标记的私聊或群聊。
- 自动改飞书待办。
- 自动写飞书多维表。
- 自动派任务。
- 自动发正式通知。
- 自动修改 dashboard 正式数据。
- 自动修改工作OS正式判断源。

### 5. 聊天资料处理原则

飞书聊天不做全量抓取。只处理：

- 王凯转发给机器人的消息。
- 王凯发给机器人的截图/语音/链接。
- 后续显式 `@AI 收录` 的消息上下文。

## 三、王凯使用方式

### 1. 会议

发给机器人：

```text
[会议] 选址推进会
妙记链接：xxx
重点：看深圳湾租金、dashboard字段、圣祥下一步动作。
```

也可以只发妙记链接 + 语音说明。

### 2. 微信

发给机器人：

```text
[微信] 圣祥-深圳湾租金
下面几张图是一组。
```

然后发截图，再发语音：

```text
这几张图是圣祥关于深圳湾租金的微信，他说租金还没拿到准确口径，但商场催推进。请判断它和 site 初筛、dashboard 展示有没有关系。
```

### 3. 电话

发给机器人：

```text
[电话] 商场方沟通
语音说明：刚才电话结论是 xxx，可能影响 xxx。
```

### 4. 想法

发给机器人：

```text
[想法] 事项编排入口
语音或文字：xxx
```

### 5. 开始编排

当晚或第二天早上发：

```text
开始编排
```

机器人执行：

1. 读取今天机器人收件箱资料。
2. 展开显式提供的妙记/云文档链接。
3. 读取 `lann-site` 项目状态。
4. 读取 `lann-dashboard` 项目状态。
5. 读取工作OS判断源候选。
6. 输出事项编排。

## 五、数据对象

### 1. source_packet

原始资料包：

- 资料类型：会议 / 文档 / 聊天 / 微信 / 电话 / 想法 / 项目状态。
- 来源：飞书机器人 / 妙记 / 云文档 / 转发消息 / 本地项目日志。
- 时间。
- 原始链接。
- 附件引用。
- 语音转写。
- 王凯补充说明。
- 是否需要展开读取。

### 2. derived_work_item

派生事项：

- 事项标题。
- 关联对象。
- 关联项目。
- 事项类型。
- 优先视图。
- 依赖。
- 冲突。
- 组合机会。
- 是否可能影响原方案。
- 建议动作。
- 原始资料引用。

## 六、项目状态读取

### 1. lann-site

读取：

- `AI_STATUS.md`，如存在。
- `DEVELOPMENT_LOG.md`
- `DECISIONS.md`
- `docs/AI_*.md`
- `ai/tasks/*.json`

### 2. lann-dashboard

读取：

- `AI_STATUS.md`
- `DEVELOPMENT_LOG.md`
- `DECISIONS.md`
- `ROADMAP.md`，如有。
- 其他项目状态 MD。

前提：王凯提供 dashboard 本地路径。

### 3. 工作OS

读取：

- 判断源候选 raw。
- 最近沉淀内容。
- 会议复盘。
- AI协作规则。

## 七、第一阶段实现范围

先做：

1. 飞书机器人收件入口。
2. 每晚 21:30 提醒。
3. 手动触发“开始编排”。
4. 机器人输出今日事项编排。
5. 读取本地 `lann-site`、`lann-dashboard`、工作OS 状态文件。
6. 显式链接的云文档/妙记展开读取。

暂不做：

1. 自动全量监听飞书所有聊天。
2. 自动全量同步微信。
3. 自动派任务。
4. 自动写业务表。
5. 自动修改正式判断源。

## 八、需要王凯配合

1. 提供或确认飞书机器人连接方式。
2. 确认机器人会话名称。
3. 确认每日提醒时间，默认 21:30。
4. 提供 `lann-dashboard` 本地路径。
5. 提供 dashboard 项目的状态文件命名习惯，如与 `AI_STATUS.md / DEVELOPMENT_LOG.md / DECISIONS.md` 不同。
