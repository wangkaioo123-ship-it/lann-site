# lann-site 数据身份契约 v0.1

## 目的

避免门店换铺、合同更新、飞书底表刷新后，BI 经营数据、租金和点位属性通过同一个旧 ID 串到不同实体。

## 四类对象

| 对象 | 含义 | 建议稳定键 |
|---|---|---|
| 经营门店 | Hanson BI 中持续经营和记账的门店 | Hanson 门店 ID |
| 物理点位 | 一处真实地址及落位 | 独立点位 ID；换地址必须新建 |
| 租赁合同 | 一段租约及租金条件 | 飞书 `record_id` 或合同编号 |
| 分析经营期 | 某门店在某物理点位上的有效经营区间 | 经营门店 ID + 点位 ID + 起止日期 |

`门店序号` 不能在未验证唯一性和稳定性前，同时充当上述四类对象的主键。

## 强制规则

1. 有效底表记录不得缺点位 ID。
2. 一个用于关联的点位 ID 不得对应多个物理位置或多条合同记录。
3. 映射目标必须存在，且刷新底表后必须重新检查门店名称与目标 ID。
4. 每家门店每个月只能有一条经营结果记录。
5. 更新任一输入后，必须重建全部下游结果，并生成 `pipeline_manifest.json`。
6. 输入存在契约 `ERROR` 时，不得把下游标签当成正式业务判断。
