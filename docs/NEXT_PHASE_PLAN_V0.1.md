# lann-site 下一阶段计划 v0.1

> 本文是 2026-07 的历史计划，不再代表当前生产状态。2026-08-29 的真实部署、正式数据边界和专业分析反馈闭环以 `README.md` 与 `docs/PROFESSIONAL_ANALYSIS_FEEDBACK_V0.1.md` 为准。

## 历史基线（2026-07）

- 门店身份、迁址和装修期已可追溯；过渡月不会混入单一物理点位。
- 经营营收已接续到 2026-06，当前趋势可看到 2026-07-17。
- 经济性 Gate 已独立于归因样本，但“完整好店”仍缺客户结构、复购和波动验证。
- 项目仍在本地运行，Hanson 服务器没有正式部署和验收记录。

## P0：把数据链变成稳定日常能力

1. 在 Hanson 服务器部署只读刷新和分析重建任务。
2. 每日记录成功时间、数据截止日、覆盖门店数和异常门店；失败时可见告警。
3. 处理3条历史映射快照告警：温州滨江万象城、滨江万芊荟、盈丰天地，确认是正常更名/历史错误后固化别名。
4. 验收标准：连续7天自动运行；无线上写入；完整月与本地结果一致；密钥不入库。

进展（2026-07-18）：Hanson已完成独立服务器目录、用户、venv、只读deploy key和飞书凭证，底表抽取已验证。仓库已补齐完整批处理入口、跟踪版门店映射、运行状态文件和07:30 systemd timer模板。本地按服务器顺序29秒跑通；待代码push、服务器BI API只读凭证确认和管理员安装timer。

## P1：完成“好店”判断，不只看营收和租金

1. 从 Hanson 查找 2026-04 以后的新客、老客、复购、客单和理疗师产值实际字段，区分实际值与目标值。
2. 建立三层判断：经济性达标、客户结构健康、经营波动可接受。
3. 先人工复核4个经济性达标点位和典型反向点位，校准阈值，不直接让模型自定规则。
4. 验收标准：每个“好店”结论都能说明营收、租售比、新客/老客、波动和选址因素各自贡献。

进展（2026-07-18）：已找到并接入 `operate_monthly_indicator_data`，新客、老客、客次、留存率和返店频次已更新到2026-06；二次到店率因公式误差暂未接。已生成4家经济性达标店的完整证据表，等待业务阈值确认。

## P2：从历史解释进入候选点位判断

1. 以太子湾等未开业点位作为首批候选案例，补齐租金、面积、开业计划、商场客流、交通、周边人口和竞店。
2. 用已确认的正向/反向门店建立可比店组，不直接用全网平均值预测。
3. 输出“建议进入、条件进入、暂缓”及关键假设，不输出伪精确营业额。
4. 验收标准：候选结论能追溯到相似店、关键因子、风险和开业后验证指标。

## P3：稳定后再接展示层

方法和口径稳定后，再通过飞书数据契约向 lann-dashboard 提供结果；lann-site 不承接工作台、加盟服务或财务结算流程。
